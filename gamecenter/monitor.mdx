服务端进程偶尔会“假死”：进程还在、任务管理器里看得到，但主线程卡住不再响应，玩家连不上、操作没有反应，而 GameCenter 界面还显示“已启动”。

GameCenter 的监控会定时“敲一下”每个受管程序的主窗口：敲得通说明正常；连续敲不通，就判定这个程序已经无响应，然后按配置**只记录日志**或**自动重启它**。

<Note>
  这一页只讲“程序假死”这一种情况。手动停止服务器、正常关服走的是另一套流程，不受这里的参数影响。
</Note>

## 两种处理方式

| 动作 | `Action` 取值 | 实际行为 | 建议 |
| --- | --- | --- | --- |
| 只记录 | `log`（默认） | 只在日志里记一条 `[无响应]`，不动程序 | 新服或第一次配置时先用这个 |
| 自动重启 | `restart` | 结束旧进程 → 按当前设置重新拉起 → 等它自己报告启动完成 | 观察一段时间确认没有误报后再开 |

<Warning>
  默认是“只记录”，不会动任何进程。要启用自动重启，必须把 `Action` 显式改成 `restart`。
</Warning>

## 判定时间线

| 阶段 | 默认耗时 | 说明 |
| --- | --- | --- |
| 单次探测超时 | 1 秒 | 每次探测最多等 1 秒，等不到回应算一次失败 |
| 探测间隔 | 5 秒 | 每隔 5 秒探测一次 |
| 连续失败 | 3 次 | 中间只要成功一次，计数立刻清零 |
| **判定无响应** | **最快 15 秒，实测 18~22 秒** | 15 秒 = 5 秒 × 3 次 |
| 结束旧进程并确认退出 | 约 3 秒 | 结束后要等它真正退出 |
| 重新拉起并等待启动完成 | 约 5~15 秒 | 取决于程序自身的启动速度，最多等 30 秒 |

<Note>
  程序刚启动或刚被重启后，**10 秒内不会被判定**（静默期）。启动慢的程序不会一上来就被误杀。
</Note>

## 配置

配置写在 GameCenter 同目录的 `Config.ini` 的 `[Monitor]` 段。第一次运行时 GameCenter 会自动把默认值写进去，正常不需要手写键名。

```ini
[Monitor]
Enabled=1
Action=log
Modules=RunGate
IntervalMS=5000
ProbeMS=1000
FailCount=3
SettleMS=10000
KillWaitMS=5000
RetryDelayMS=60000
MaxRestartPer10Min=5
GlobalRestartMax=8
DumpOnKill=0
LogDir=
LogKeepDays=7
```

### 参数说明

| 参数 | 默认值 | 取值范围 | 说明 |
| --- | --- | --- | --- |
| `Enabled` | `1` | 0 / 1 | 总开关。`0` 表示不做无响应探测 |
| `Action` | `log` | `log` / `restart` | 判定无响应后的处理方式 |
| `Modules` | `RunGate` | 模块名列表 | 要监控哪些程序，见下一节 |
| `IntervalMS` | `5000` | 1000 ~ 60000 | 探测间隔（毫秒） |
| `ProbeMS` | `1000` | 100 ~ 间隔值 | 单次探测最多等多久（毫秒） |
| `FailCount` | `3` | 1 ~ 20 | 连续失败几次算无响应 |
| `SettleMS` | `10000` | 0 ~ 300000 | 程序启动/重启后的静默期（毫秒），期间不判定 |
| `KillWaitMS` | `5000` | 1000 ~ 120000 | 结束旧进程后，等它真正退出的上限（毫秒） |
| `RetryDelayMS` | `60000` | 10000 ~ 3600000 | 重启失败后隔多久再试（毫秒） |
| `MaxRestartPer10Min` | `5` | 1 ~ 100 | 同一台程序 10 分钟内最多重启几次 |
| `GlobalRestartMax` | `8` | 1 ~ 100 | 全服 10 分钟内最多重启几台次 |
| `DumpOnKill` | `0` | 0 / 1 | 重启前是否保存一份内存快照（排障用，占磁盘） |
| `LogDir` | 空 | 目录路径 | 文件日志目录。**留空则不写文件日志** |
| `LogKeepDays` | `7` | 1 ~ 365 | 文件日志保留天数，过期自动清理 |

### Modules 怎么写

- 多个模块用英文逗号分隔，例如 `RunGate,M2Server`。
- 名称不区分大小写，前后空格会被忽略。
- 可用的模块名：`DBServer`、`LoginSrv`、`LogServer`、`M2Server`、`LoginGate`、`SelGate`、`RunGate`。
- 留空（`Modules=`）= 监控全部已启动程序。
- 默认只监控 `RunGate`，也就是最容易被玩家直接感知的入口。

<Warning>
  名称写错不会报错，只会等于“这个模块没被监控”。改完建议看一眼启动日志里打印的当前配置，确认生效。
</Warning>

### 日志放在哪

- `LogDir` 留空：只在 GameCenter 界面里显示，不落文件。
- `LogDir` 填了目录：每天一个文件，文件名形如 `GameCenter-20261107.log`。
- 日志超过 `LogKeepDays` 天会自动删除。

```ini
[Monitor]
LogDir=D:\MirServer\GameCenterLog
LogKeepDays=7
```

## 建议的启用步骤

1. 保持 `Action=log`，让服务器跑 1~2 天。
2. 翻日志里出现 `[无响应]` 的记录，对照当时玩家的反馈：如果玩家毫无察觉，说明探测过于敏感，可调大 `IntervalMS` 或 `FailCount`。
3. 确认记录可信后，把 `Action` 改成 `restart`，先只监控 `RunGate`。
4. 稳定运行几天后，再逐台把 `M2Server`、网关类程序加进 `Modules`。

## 日志怎么读

```text
[监控] 启用 动作=只告警 模块=RunGate 周期=5000ms 超时=1000ms 判死=3次 静默=10000ms ...
[无响应] 游戏网关[0](PID=2312) 连续3次探测超时 停=16000ms 单次=1000ms，正在强制重启...
[重启] 游戏网关[0](PID=2312) 已强制结束
[重启] 游戏网关[0] 正在重新启动...
[重启] 游戏网关[0] 重启完成(PID=5480)
```

| 日志片段 | 含义 |
| --- | --- |
| `[监控] 启用 动作=... 模块=...` | GameCenter 启动时打印的当前生效配置，先看这一条 |
| `[无响应] … 观测模式不处理` | `Action=log`，只记录，没有动作 |
| `[无响应] … 正在强制重启` | 判定为无响应，开始重启 |
| `[无响应] … 已恢复响应` | 判定的空隙里程序自己恢复了，不再处理 |
| `[重启] … 已强制结束` | 旧进程已经结束 |
| `[重启] … 正在重新启动` / `… 重启完成(PID=xxx)` | 新进程已拉起，并收到了它的“启动完成”回报 |
| `[重启] … 拉起失败(错误码=…)` | 没能拉起，会在 `RetryDelayMS` 后重试 |
| `[重启保护] … 10 分钟内已重启 N 次` | 触发单台上限，这台不再自动重启 |
| `[重启保护] … 疑似系统性问题` | 触发全局上限，全部自动重启暂停 |
| `[监控] … 找不到可探测的主线程窗口，暂不判定` | 这个程序没有可供探测的窗口，跳过（每个程序只提示一次） |

## 安全保护：不会无限重启

- **单台上限**：同一台程序 10 分钟内最多重启 5 次（`MaxRestartPer10Min`），超过就停手，等人工检查。
- **全局上限**：10 分钟内全服最多重启 8 台次（`GlobalRestartMax`）。短时间内多台一起挂，通常是机器或系统性问题，继续自动重启只会雪上加霜。
- **失败退避**：拉起失败不会立刻重试，等 `RetryDelayMS`（默认 60 秒）再来一轮。
- **结束不掉的进程**：连续三次结束不生效，就暂停这台程序的自动重启，并提示人工处理。
- **串行执行**：同一时间只处理一个重启，不会几台一起改写共享的配置文件。

## 常见误区

<AccordionGroup>
  <Accordion title="关闭 Enabled 后，程序崩溃了还会被拉起吗？">
    会。`Enabled=0` 只关掉“假死探测”；程序**自己退出**（崩溃、被外部结束）属于另一条保护，仍然会自动拉起。两件事互不影响。
  </Accordion>
  <Accordion title="我在 GameCenter 里点“停止游戏服务器”，会被当成假死吗？">
    不会。启动和停止流程进行期间，监控不介入；程序停止过程中的“窗口消失”也不计为失败。
  </Accordion>
  <Accordion title="开了“窗口嵌入”要不要紧？">
    用自动重启时建议关闭窗口嵌入。窗口嵌入会让探测更容易误超时，GameCenter 启动时如果检测到这种情况，会打印一条提示。
  </Accordion>
  <Accordion title="机器很卡的时候，会不会把一批程序全判成无响应？">
    有可能。所以有单台上限和全局上限兜底：全局上限触发后会自动暂停全部自动重启。如果这种情况经常出现，先把 `Action` 调回 `log`，并适当调大 `IntervalMS`。
  </Accordion>
  <Accordion title="探测会不会给程序增加负担？">
    负担极小。每次探测只发一条空消息，正常情况下立即返回，不涉及网络和磁盘。
  </Accordion>
  <Accordion title="程序没有主窗口，能被监控吗？">
    不能。监控是“敲窗口看它是否响应消息”，没有可探测窗口的程序会被跳过，日志里会有一条 `找不到可探测的主线程窗口，暂不判定`，也不会产生无响应记录。
  </Accordion>
</AccordionGroup>

## 调参速查

| 目标 | 改哪个参数 | 建议 |
| --- | --- | --- |
| 保持默认 | — | 5 秒探测、连续 3 次、15 秒判定，够用 |
| 机器较慢、担心误判 | `IntervalMS` / `SettleMS` | `10000` / `20000` |
| 想更快发现 | `FailCount` | 改成 `2`（约 10 秒判定，误报风险上升） |
| 只重启最重要的程序 | `Modules` | 例如 `M2Server,RunGate` |
| 暂时只观察不处理 | `Action` | `log` |
| 排障时留现场 | `DumpOnKill` | 临时改成 `1`，用完改回来 |

<Note>
  改完 `Config.ini` 需要重启 GameCenter 才生效。
</Note>
